# Release communication

- Write all public changelogs and GitHub release notes in English, regardless of the conversation language or interface locale.
- Write for players: explain what changed, what was fixed, and how to use new features in everyday language.
- Keep internal implementation details, API names, protocol mechanics, test results, tooling, and AI/development workflow out of player-facing release notes.
- State relevant requirements and known limitations accurately. Do not describe unverified behavior as confirmed.
- Keep GitHub release notes consistent with the corresponding entry in CHANGELOG.md. Include straightforward installation instructions.
- Release downloads should contain only the installable addon ZIP plus GitHub's automatic source archives. Keep screenshots in the README, not as release assets.
